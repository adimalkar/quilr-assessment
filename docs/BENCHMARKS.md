# Benchmarks

Generated by `uv run python scripts/bench.py` on Python 3.13.15. Local loopback, single machine.

### 1. Redactor cost per delta (4-character deltas ≈ 1 token)

| input | deltas | p50 µs | p99 µs | max held chars | stream == batch |
|---|---:|---:|---:|---:|:-:|
| realistic text (2% PII) | 279,205 | 10.0 | 33.5 | 24 | ✓ |
| pathological: 200 KB digit run | 50,000 | 11.4 | 21.6 | 68 | ✓ |
| pathological: 200 KB letter run | 50,000 | 7.2 | 12.6 | 68 | ✓ |

### 2. Time to first content token (40 runs each; provider emits a 4-char delta every 10 ms)

| path | p50 ms | p95 ms |
|---|---:|---:|
| provider direct (no guardrail) | 1.4 | 2.3 |
| through guardrail | 13.4 | 15.1 |
| through guardrail, 50-char email opens the stream | 196.7 | 198.9 |

The guardrail adds about one held-back word. The worst case is inherent to exact redaction: text that might still turn out to be an email can't be released before it's known not to be one. The bound is the PII length, not the response length.

### 3. Failover deadline precision (50 concurrent requests, primary takes 10 s)

| min ms | p50 ms | p95 ms | max ms | served by |
|---:|---:|---:|---:|---|
| 3056 | 3114 | 3158 | 3164 | secondary |

Budget: 3000 ms. The excess over 3000 ms is cancellation, then the backup round-trip, then SQLite reserve and reconcile. Nothing waits for the slow primary.
